## 핵심 개념

- 생성형 AI가 보편화된 학습 환경에서, 학습자가 자신의 AI 활용 방식을 스스로 인식하고
  성찰하도록 돕는 시스템. AI를 무조건 배척/의존하는 이분법을 넘어, **학습 이벤트** 단위로
  AI 개입의 목적·맥락·기여도를 진단.
- 핵심 이론: 메타인지(Metacognition), 인지적 구두쇠(Cognitive Miser), 바람직한 어려움
  (Desirable Difficulty) / 생산적 마찰(Productive Friction), 블룸의 교육목표 분류(Bloom's
  Revised Taxonomy).
- 3단계 파이프라인: **메타인지 기반 사전 진단 → 사용자 프롬프트 로그 입력(교차검증) →
  학습 확인 질문(전이 검증)**

**Phase 3 비고**: 산출물 유형 축의 공수 절감 효과는 A/B/C/D 4개 유형 최초 구축 시점이
아니라, 향후 기존 4개 유형 중 하나에 속하는 신규 전공이 추가될 때부터 발생함(매트릭스
재사용 가능).

**Phase 6 스코프 결정**: 코드(CogniTrieve) 실제 리팩토링은 포함하지 않고, 설계 문서
(`07`) 갱신까지만 진행하기로 확정.

**Phase 7 비고**: '학습 유형(과제/수강/시험)'을 새로운 최상위 축으로 승격하고, 기존
산출물 유형(A/B/C/D)은 "과제" 학습유형 내부 하위 분류로 재정의함. Phase 7.0~7.2 모두
완료 — 로드맵상 설계 작업이 전부 마무리됨.

**액션 아이템 완료**: `02`, `03`, `04`, `05`, `06`, `07` 전체에 "본 문서는 학습 유형
'과제' 전용" 스코프 안내를 상단에 추가 완료. (`00`, `01`은 프로젝트 전반 배경 문서라
스코프 안내 대상에서 제외.) `01`은 팀원 정보(김도현 관련 서술)도 정정 완료.

**통합 검토 완료 (`09`)**: 학습유형 3종 통합 비교표 작성, 설계 전체 재검토를 통해
정합성 이슈 5건 식별 — **5건 모두 채택·반영 완료**: 등급별 임계값 차등 적용(`07`),
Health Score 균등가중+보정계획(`07`), 이벤트 번호 색인표(`09`), 진단 스키마
`hotspot_tier` 필드 추가(`09`), 유형 B(CS) 실제 진단 문항 반영(`07`, 1학기 원본
`1_사전진단.py` 확보). 상세는 `09` 5절 참조.

## 구현 로드맵 (Implementation, `10` 참조)

설계 로드맵(위 표)과는 별도로 번호를 매긴 **구현 Phase 1~5**로 진행. 기술 스택은
**Streamlit 유지 + Supabase(Postgres) 추가**로 결정(1인 개발 체제, 실제 학생 다수
대상 파일럿 목표).

**외부 검토 반영**: 작성 직후 타 AI 세션에 객관적 검토를 요청해 7개 지적사항을 받았고,
프로젝트 실정에 맞게 취사선택해 반영했다(4개 원안 채택, 3개는 완화) — Phase 순서 조정,
`case_id` 스키마 버그 수정, RLS/IRB/일정 추정/비용·보존정책 보강. 상세 판단 근거는 `10`
상단 상태 노트 참조.

| 구현 Phase | 내용 | 예상 기간 | 상태 |
|---|---|---|---|
| 1 | 데이터 계층(Supabase dev/prod, 케이스 시딩, 동의 화면, RLS, IRB 확인 착수) | 1주 | ⬜ 예정 |
| 2 | 1단계 사전진단 일반화 (6개 케이스, 등급별 임계값) | 1주 | ⬜ 예정 |
| 3 | 2단계 로그분석 일반화 (난이도 순: 자기보고→코드→텍스트→수식, 균등가중 Health Score) | 2~3주 | ⬜ 예정 |
| 4 | 3단계 학습확인질문 일반화 (신규 포맷 2종) | 1주 | ⬜ 예정 |
| 5 | 파일럿 준비 및 배포 (비용/보존정책/부하 점검 포함) | 1주 | ⬜ 예정 |

상세 작업 항목·DB 스키마·완료 기준은 `10_구현로드맵.md` 참조.
