# 02. 전공 다양화 설계 방향 (2026 여름방학 확장)

## 확장 배경

1학기 성과물(CogniTrieve)은 'CS 전공 대학생의 코딩·보고서 작성'과 '교양 독서 후 토론·
보고서 작성' 2개 시나리오에 한정. 여름방학 확장의 목표는 **'다양한 전공 대학생들의
수강, 과제, 시험이라는 여러 학습 유형'**으로 범위를 넓히는 것.

우선순위: ① 전공 다양화 → ② 학습 유형 다양화(수강/시험) 순으로 진행.

## 핵심 설계 갈림길: 전공명 축 vs 산출물 유형 축

| | 전공명 기반 접근 | 산출물 유형 기반 접근 |
|---|---|---|
| 방식 | "철학", "물리학"처럼 학과 단위로 시나리오 구성 | 전공과 무관하게 "코드형", "글쓰기형", "수리형" 등 산출물 카테고리로 구성 |
| 문제점/장점 | 전공이 늘 때마다 Bloom 매트릭스를 매번 새로 제작해야 함 (지난 학기 CS 매트릭스 제작에도 상당한 공수 소요) | 카테고리 하나로 여러 학과의 과제를 동시에 커버 가능 → 설계 자산 재사용성 ↑ |

## 채택 방향: 하이브리드 (계층 구조)

```
상위 축: 산출물 유형 (Output Type)  ← 확장성/재사용성 담당 (Bloom 매트릭스, 진단 문항 등 무거운 설계 자산)
  └ 하위 축: 전공(도메인) 페르소나  ← 구체성/현실감 담당 (구체적 시나리오, 지난 학기 설계 철학 계승)
```

산출물 유형을 시스템의 핵심 엔진 축으로 두고, 전공은 그 위에 현실감을 입히는 페르소나
레이어로 배치. 전공이 늘어나도 새로운 산출물 유형이 아니면 기존 매트릭스에 얹기만 하면
됨.

## 산출물 유형 4분류

| 유형 | 설명 | 지난 학기 대응 | 대표 시나리오 |
|---|---|---|---|
| **A. 텍스트/논증형** | 독서 기반 에세이, 비평, 리포트 | 시나리오 1 승계 | 시나리오 1 (교양) |
| **B. 코드/구현형** | 프로그래밍 과제, 알고리즘 구현 | 시나리오 2 승계 | 시나리오 2 (CS) |
| **C. 수리/문제해결형** | 수식 유도, 증명, 계산 문제 풀이 | 신규 | 시나리오 3 (자연과학/공학) |
| **D. 창작/디자인형** | 작품 제작, 디자인, 기획안 | 신규 | 시나리오 4 (예체능/디자인) |

이 4유형의 조합으로 대부분의 전공을 커버 가능: 인문(A), 자연과학(A+C), 공학(B+C),
예체능(D), 사회과학(A+C) 등.

## 대표 버티컬(전공 페르소나) 선정 — 4개

1. 교양(인문/철학) — 에세이 작성 (유형 A 대표, 기존)
2. 컴퓨터공학(CS) — 코딩 과제 (유형 B 대표, 기존)
3. 자연과학/공학 — 일반물리학 문제풀이 (유형 C 대표, **신규**)
4. 예체능/디자인 — 브랜드 아이덴티티 기획 (유형 D 대표, **신규**)

> 검토 결과: 4개 시나리오 모두 실생활에서 찾아볼 수 있는 현실적인 설정으로 확인됨.
> 특히 예체능 영역을 순수미술이 아닌 '디자인'으로 좁힌 것이 적절하다고 판단.
