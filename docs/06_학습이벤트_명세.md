# 06. 학습 이벤트(Learning Event) 명세

핫스팟으로 식별된 지점을 시스템이 인식·개입할 수 있는 단위인 **'학습 이벤트'**로
규격화. 추후 자가진단 도구 구현을 고려해 이벤트 ID를 부여한다.

## 이벤트 유형 택소노미 (Phase 4.5 공식화)

1학기~2차 세션에 걸쳐 이벤트마다 "유형"을 개별 부여해왔으나, 번호(3, 4)만 쓰이고 전체
목록이 별도로 정의된 적은 없었다. `05_AI개입깊이_핫스팟매핑.md`의 Level 1(단순보조)/
Level 2(부분증강)/Level 3(전면대체) 프레임과 연결해 5개 유형으로 공식화한다.

| 번호 | 유형명 | 정의 | `05` 개입 Level 대응 | 비고 |
|---|---|---|---|---|
| 1 | 정보탐색 (Search) | 사실·문법·API 등 단편 정보 검색 보조 | Level 1 | 위험도 낮아 현재까지 정식 이벤트로 등록된 사례 없음 |
| 2 | 이해증강 (Augmentation) | 구조·아이디어·대안 제시 등 사고 보조 | Level 2 | 위 1과 동일하게 아직 미등록 |
| 3 | 결과물 생성 (Generation) | 학습자가 직접 만들어야 할 결과물(코드/글/수식/시안)을 AI가 최초로 생성·대행 | Level 3 | 가장 빈번한 유형 |
| 4 | 문제 해결 및 검토 (Troubleshooting) | 이미 존재하는 결과물의 오류 원인 파악·검증을 AI에 위임 | Level 3 | 원인 역추적·검증 생략이 핵심 |
| 5 | **사후 합리화 (Post-hoc Rationalization)** *(신규)* | 이미 완성된 결과물을 놓고, 그 결과물을 만든 실제 사고 과정과 무관하게 AI가 "그럴듯한 설명/서술"을 사후적으로 지어내는 것을 그대로 채택 | Level 3 | 서술과 실제 논리의 불일치가 핵심 위험 — 결과물 자체는 이미 완성돼 있다는 점에서 유형 3과 구분 |

**유형 3 vs 유형 5 구분 기준**: 유형 3은 "아직 존재하지 않는 결과물"을 AI가 만들어내는
것(예: 에세이 본문, 코드, 수식, 디자인 시안)이고, 유형 5는 "이미 존재하는 결과물"에
대한 사후적 설명·정당화를 AI가 대신 지어내는 것(예: 보고서의 트러블슈팅 서술, 기획
의도서)이다. 후자는 결과물 자체보다 **메타인지적 성찰의 진실성**이 훼손된다는 점에서
별도 진단이 필요해 신설했다.

**유형 1, 2 관련 메모**: 현재까지 식별된 학습 이벤트는 전부 Level 3(전면대체) 개입에서만
발생한다 — 즉 "결과물을 통째로 대체"당하는 순간이 리플렉션이 필요한 지점이기 때문이다.
Level 1·2는 상대적으로 안전한 개입으로 간주해 정식 이벤트로 등록하지 않았으나, Phase 5
(진단 문항 설계) 단계에서 Level 1·2 과다 사용 패턴도 진단 대상으로 다룰지 재검토 필요.

> **상태**: 시나리오 1~4 명세 및 이벤트 유형 택소노미 공식화(Phase 4.5) 완료.
> 시나리오 3, 4는 `05_AI개입깊이_핫스팟매핑.md`의 핫스팟과 `04_블룸매트릭스_유형별.md`의
> 최고위험 교차점(수식화/답검증, 컨셉발상/시안제작)을 Trigger 기준으로 매핑해 작성.
> 시나리오 2(CS)의 3연쇄 이벤트 패턴을 동일하게 적용. Phase 4.5에서 유형 5(사후 합리화)를
> 신설하고, 기존 보고서 자동생성·디자인 기획서 사후작성 이벤트를 유형 3→5로 재분류.

## [이벤트 1] 교양 과목: '전면적 작문 위임' — 유형 A

학생이 초안까지는 스스로 고민했으나, 이를 논리적이고 매끄러운 긴 글로 완성하는
'작문(표현)의 고통'을 회피하는 이벤트.

- **이벤트 ID**: `event_essay_full_generation`
- **유형**: 3. 결과물 생성 (Generation)
- **발생 상황(Trigger)**: 독서 후 요약과 파편적 초안 작성까지 마쳤으나, 완성된 에세이
  형태로 엮어내는 과정이 막막할 때
- **학생의 행동**: 요약본·초안을 프롬프트에 넣고 "이 내용을 바탕으로 제출용 에세이
  전체를 완성해서 써줘"라고 지시
- **시스템의 진단 포인트**:
  - "AI가 완성한 문장의 흐름과 논리 전개가 나의 원래 의도(초안)와 100% 일치하는가?"
  - "스스로 문장을 다듬고 논리를 전개하는 '작문 훈련' 기회를 잃어버리지 않았는가?"

## [이벤트 2] 전공 과목: 코딩 과제 파이프라인 (3개 연속 이벤트) — 유형 B

코드를 짜고, 고치고, 보고서를 쓰는 전 과정을 AI에 외주 주는 형태. 3개 이벤트로 쪼개어
각각 다른 질문을 던지도록 설계.

### 이벤트 2-1: '요구사항 기반 초기 코드 통짜 생성'
- **이벤트 ID**: `event_code_initial_generation`
- **유형**: 3. 결과물 생성 (Generation)
- **학생의 행동**: 과제 조건·목표만 추출해 AI에 입력 후, 컴파일 가능한 전체 코드를
  요구해 복사-붙여넣기
- **진단 포인트**: "복사한 코드 내부의 핵심 자료구조·알고리즘이 왜 그렇게 선택되었는지
  설명할 수 있는가?"

### 이벤트 2-2: '인지적 구두쇠식 로그 디버깅'
- **이벤트 ID**: `event_code_blind_debugging`
- **유형**: 4. 문제 해결 및 검토 (Troubleshooting)
- **학생의 행동**: 컴파일 오류 발생 시 원인 분석 없이 에러 메시지와 코드를 그대로
  복붙해 해결된 코드를 요구
- **진단 포인트**: "AI가 수정한 코드의 어느 줄이 문제를 해결했는지, 애초에 왜 오류가
  발생했는지 원인을 명확히 이해했는가?"

### 이벤트 2-3: '구현 결과물 기반 보고서 자동 생성'
- **이벤트 ID**: `event_report_auto_generation`
- **유형**: 5. 사후 합리화 (Post-hoc Rationalization) *(Phase 4.5 재분류: 3→5)*
- **학생의 행동**: 코드가 정상 작동하자 완성된 코드를 주고 "제출용 기술 보고서를
  작성해줘"라고 요구
- **진단 포인트**: "보고서에 서술된 '문제 해결 과정'이나 '어려웠던 점'이 실제 경험을
  정직하게 반영하고 있는가?"

## [이벤트 3] 자연과학/공학: 물리 문제풀이 파이프라인 (3개 연속 이벤트) — 유형 C

문제 조건을 수식으로 세우고, 계산하고, 검증하는 전 과정을 AI에 외주 주는 형태.
CS의 '코드작성→디버깅→보고서' 3연쇄와 대응되며, 각각 다른 실패 지점을 겨냥한다.

### 이벤트 3-1: '현상-수식 변환 전면 위임'
- **이벤트 ID**: `event_math_formulation_delegation`
- **유형**: 3. 결과물 생성 (Generation)
- **발생 상황(Trigger)**: 문제 조건과 관련 개념까지는 파악했으나, 이를 방정식/수식으로
  세우는 단계(수식화)에서 막힐 때
- **학생의 행동**: 문제 텍스트를 그대로 프롬프트에 넣고 "이 상황을 수식으로 세워줘"라고
  요구, 제시된 수식을 그대로 수용해 다음 단계로 진행
- **진단 포인트**:
  - "이 수식의 각 항이 어떤 물리 법칙에서 도출되었는지 직접 설명할 수 있는가?"
  - "AI가 세운 접근(예: 에너지 보존) 대신 다른 방법(예: 운동량 보존)은 왜 안 되는지
    설명할 수 있는가?"
- **매트릭스 대응**: `04` 유형 C 매트릭스 2행×3열(수식화) — **최고위험**

### 이벤트 3-2: '전개 과정의 블랙박스화'
- **이벤트 ID**: `event_math_blind_calculation`
- **유형**: 3. 결과물 생성 (Generation)
- **발생 상황(Trigger)**: 수식은 스스로 세웠으나, 다단계 대수적 전개나 적분 등 계산이
  복잡해질 때
- **학생의 행동**: 세운 수식만 입력하고 "이거 풀어줘"라고 요구, 중간 전개 과정 확인 없이
  최종 값만 그대로 옮겨 적음
- **진단 포인트**:
  - "전개 중 특정 줄에서 다음 줄로 넘어갈 때 어떤 대수적 규칙이 적용되었는가?"
  - "AI 풀이와 다른 순서로 전개해도 같은 답이 나오는지 스스로 확인해봤는가?"
- **매트릭스 대응**: `04` 유형 C 매트릭스 3행×4열(계산 전개, 분석) — 위험

### 이벤트 3-3: '검증 없는 결과 제출'
- **이벤트 ID**: `event_math_answer_unverified`
- **유형**: 4. 문제 해결 및 검토 (Troubleshooting)
- **발생 상황(Trigger)**: AI가 도출한 최종 답을 얻은 후, 단위·자릿수·물리적 타당성
  검토 없이 그대로 제출하려 할 때
- **학생의 행동**: "이 답 맞아?"라고만 AI에 되묻고 그 확인을 최종 검증으로 착각, 직접
  차원분석이나 극단 조건 대입 등을 시도하지 않음
- **진단 포인트**:
  - "이 결과값의 단위가 물리적으로 말이 되는가?"
  - "문제의 극단 조건(예: 질량→0, 시간→∞)을 대입했을 때도 이 식이 합리적인 값을
    주는가?"
- **매트릭스 대응**: `04` 유형 C 매트릭스 4행×5열(답 검증) — **최고위험** (코드처럼
  즉각 에러가 나지 않아 오답을 자각하지 못하고 넘어갈 위험이 가장 큰 지점)

## [이벤트 4] 예체능/디자인: 브랜드 아이덴티티 기획 파이프라인 (3개 연속 이벤트) — 유형 D

컨셉을 잡고, 시안을 만들고, 그 의도를 서술하는 전 과정을 AI에 외주 주는 형태.
CS·물리와 달리 정답이 없는 **발산적 사고**가 핵심이라, 진단 포인트도 "논리가
맞았는가"가 아니라 "이것이 왜 나만의 선택인가"를 묻는 방향으로 설계했다.

### 이벤트 4-1: '컨셉 발상 전면 위임'
- **이벤트 ID**: `event_design_concept_delegation`
- **유형**: 3. 결과물 생성 (Generation)
- **발생 상황(Trigger)**: 레퍼런스 리서치까지는 진행했으나, 이를 종합해 하나의 브랜드
  컨셉으로 발산·수렴하는 단계에서 막막할 때
- **학생의 행동**: 수집한 레퍼런스와 업종 정보를 입력하고 "브랜드 컨셉 3개 뽑아줘"라고
  요구, 제시된 안 중 하나를 별다른 재구성 없이 그대로 채택
- **진단 포인트**:
  - "이 컨셉이 다른 두 후보안이 아닌 이 안이어야 하는 이유를 나의 언어로 설명할 수
    있는가?"
  - "AI가 제안하지 않은 제4의 방향을 스스로 고민해본 적이 있는가?"
- **매트릭스 대응**: `04` 유형 D 매트릭스 2행×3열(아이디어 발산) — **최고위험**

### 이벤트 4-2: 'AI 생성 시안의 무비판적 채택'
- **이벤트 ID**: `event_design_asset_full_generation`
- **유형**: 3. 결과물 생성 (Generation)
- **발생 상황(Trigger)**: 컨셉은 스스로 정했으나, 이를 로고·컬러·무드보드 등 시각
  결과물로 구현하는 과정이 막힐 때
- **학생의 행동**: 컨셉 설명을 프롬프트에 넣고 AI 이미지 생성으로 시안 전체를 뽑은 뒤,
  툴로 직접 조작·수정하는 과정 없이 결과물을 그대로 채택
- **진단 포인트**:
  - "이 시안에서 내가 직접 조정하거나 다시 그린 요소가 있는가?"
  - "AI가 제시한 색상·형태가 왜 이 브랜드 컨셉에 적합한지 설명할 수 있는가?"
- **매트릭스 대응**: `04` 유형 D 매트릭스 3행×5열(표현&시각실현) — **최고위험**
  (심체적 영역 — '내 손을 거친 결과물'인지 여부가 핵심 상실 지점)

### 이벤트 4-3: '완성 시안의 사후 합리화 서술'
- **이벤트 ID**: `event_design_rationale_post_hoc`
- **유형**: 5. 사후 합리화 (Post-hoc Rationalization) *(Phase 4.5 재분류: 3→5)*
- **발생 상황(Trigger)**: 시안이 완성된 후, 기획 의도서(왜 이런 디자인을 했는지)를
  작성해야 할 때
- **학생의 행동**: 완성된 시안 이미지만 AI에 제시하고 "그럴듯한 기획 의도서 써줘"라고
  요구, 실제 제작 당시의 판단 근거와 무관하게 사후적으로 그럴듯한 논리를 그대로 채택
- **진단 포인트**:
  - "이 서술에 담긴 논리가 실제로 시안을 만들 때 고려했던 근거와 일치하는가?"
  - "AI가 붙인 설명 중 애초에 내가 의도하지 않았던 내용은 없는가?"
- **매트릭스 대응**: `04` 유형 D 매트릭스 4행×6열(창조&정당화서술) — 위험 (CS의
  '보고서 자동 생성' 이벤트와 동일한 사후 합리화 패턴 — 서술과 실제 제작 논리의
  불일치)
